Network Monitoring & Troubleshooting

Diagnose network problems, analyze traffic, scan for open ports, and monitor bandwidth using powerful Linux command-line tools. These skills are essential for any sysadmin.

🕐 ~55 min 🎯 Intermediate 📝 5 Quiz Questions

📌 Overview

Linux provides a rich set of network diagnostic tools. Knowing which tool to reach for in different scenarios is a key sysadmin skill.

ToolPurposeLayer
pingTest basic connectivity and latencyICMP / L3
traceroute / tracepathTrace packet route to destinationICMP/UDP / L3
ss / netstatView socket connections and listening portsTransport / L4
tcpdumpCapture and analyze raw packetsAll layers
nmapPort scanning and service discoveryL3/L4

🔌 ss & netstat

ss (socket statistics) is the modern replacement for netstat, providing the same info faster.

bash — ss command
# List all listening TCP sockets $ ss -tlnp State Recv-Q Send-Q Local Address:Port Peer Address:Port Process LISTEN 0 128 0.0.0.0:22 0.0.0.0:* users:(("sshd",pid=1023)) LISTEN 0 511 0.0.0.0:80 0.0.0.0:* users:(("nginx",pid=2345))
# Show all established connections $ ss -tnp state established
# Show UDP sockets $ ss -ulnp
# Filter by port $ ss -tnp '( dport = :443 or sport = :443 )'
# Legacy netstat equivalent $ netstat -tlnp

📡 ping & traceroute

bash — connectivity tools
# Basic ping (4 packets) $ ping -c 4 8.8.8.8 PING 8.8.8.8 56(84) bytes of data. 64 bytes from 8.8.8.8: icmp_seq=1 ttl=118 time=12.3 ms --- 8.8.8.8 ping statistics --- 4 packets transmitted, 4 received, 0% packet loss
# Ping with flood (requires root) $ sudo ping -f -c 100 192.168.1.1
# Traceroute to destination $ traceroute google.com 1 192.168.1.1 1.234 ms 1.123 ms 0.987 ms 2 10.0.0.1 5.432 ms 4.321 ms 5.123 ms 3 * * * (firewall blocking)
# mtr: live traceroute with statistics $ mtr --report google.com
# tracepath (doesn't need root) $ tracepath 8.8.8.8

🎣 tcpdump — Packet Capture

tcpdump captures live network traffic and writes it to the terminal or a .pcap file for later analysis with Wireshark.

bash — tcpdump
# Capture on interface ens3 $ sudo tcpdump -i ens3
# Capture only HTTP traffic $ sudo tcpdump -i ens3 port 80
# Capture TCP SYN packets (new connections) $ sudo tcpdump -i ens3 'tcp[tcpflags] & tcp-syn != 0'
# Capture traffic from specific host $ sudo tcpdump -i ens3 host 203.0.113.5
# Save to pcap file (for Wireshark) $ sudo tcpdump -i ens3 -w /tmp/capture.pcap
# Read pcap file $ sudo tcpdump -r /tmp/capture.pcap
# Verbose with no DNS resolution $ sudo tcpdump -vvv -n -i ens3 port 443

🗺️ nmap — Network Scanner

nmap (Network Mapper) is the industry-standard port scanner. Use it to discover hosts, open ports, and running services.

⚠️
Legal Warning
Only scan networks and hosts you own or have explicit written permission to scan. Unauthorized port scanning is illegal in many jurisdictions.
bash — nmap scanning
# Basic port scan of a host $ nmap 192.168.1.1
# Scan specific ports $ nmap -p 22,80,443,8080 192.168.1.0/24
# Service version detection $ nmap -sV 192.168.1.100 22/tcp open ssh OpenSSH 8.9p1 80/tcp open http nginx 1.22.0 443/tcp open https nginx 1.22.0
# OS detection (requires root) $ sudo nmap -O 192.168.1.100
# Aggressive scan (OS + version + scripts + traceroute) $ sudo nmap -A 192.168.1.100
# Fast scan of top 100 ports $ nmap -F 192.168.1.0/24
# Scan all 65535 ports $ nmap -p- 192.168.1.100

📊 Bandwidth Monitoring Tools

iftop
Real-time bandwidth per connection on an interface
sudo iftop -i ens3
nethogs
Show bandwidth usage per process
sudo nethogs ens3
vnstat
Historical bandwidth statistics
vnstat -i ens3
iperf3
Measure network throughput between hosts
iperf3 -s / iperf3 -c server_ip
nload
Visual incoming/outgoing bandwidth graph
nload ens3
bmon
Bandwidth monitor for all interfaces
bmon

🧪 Lab Exercise

🧪
Lab 05 — Network Reconnaissance & Troubleshooting
Estimated time: 20 minutes · On your own network/VM
1
Check listening services
Run ss -tlnp to see what ports are open on your system. Identify each service.
2
Test connectivity
Ping your gateway, then 8.8.8.8, then google.com to diagnose where any connectivity issue exists.
3
Trace network path
Run traceroute 8.8.8.8 and identify each hop. Note any timeout hops (*).
4
Capture SSH traffic
In one terminal, run sudo tcpdump -i any port 22 -n. In another, SSH to localhost. Observe the packets captured.
5
Scan your own machine
Run nmap -sV localhost to see what services nmap detects on your machine. Compare with ss -tlnp output.
