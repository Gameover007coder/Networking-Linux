iptables & nftables

iptables is the classic Linux firewall framework that uses netfilter hooks in the kernel. Learn to filter packets, perform NAT, and build complete firewall rulesets. We also cover nftables — the modern replacement.

🕐 ~60 min 🎯 Intermediate 📝 5 Quiz Questions 🧪 1 Lab Exercise

📌 Overview

iptables works with the Linux kernel's netfilter framework. Packets traverse a series of tables, each containing chains of rules. Each rule matches packet attributes and specifies a target (action).

📝 Writing Rules

bash — iptables rule examples
# View all rules $ sudo iptables -L -v -n --line-numbers
# Set default policies (deny all, allow out) $ sudo iptables -P INPUT DROP $ sudo iptables -P FORWARD DROP $ sudo iptables -P OUTPUT ACCEPT
# Allow established/related connections $ sudo iptables -A INPUT -m conntrack \ --ctstate ESTABLISHED,RELATED -j ACCEPT
# Allow loopback $ sudo iptables -A INPUT -i lo -j ACCEPT
# Allow SSH (port 22) $ sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT
# Allow HTTP and HTTPS $ sudo iptables -A INPUT -p tcp -m multiport --dports 80,443 -j ACCEPT
# Allow ICMP (ping) $ sudo iptables -A INPUT -p icmp -j ACCEPT
# Block specific IP $ sudo iptables -A INPUT -s 203.0.113.5 -j DROP
# Rate-limit SSH (anti-brute-force) $ sudo iptables -A INPUT -p tcp --dport 22 \ -m limit --limit 3/min -j ACCEPT
# Delete rule by line number $ sudo iptables -D INPUT 5
# Flush all rules in filter table $ sudo iptables -F
🚨
Don't lock yourself out!
Always allow your current SSH session (port 22) before setting INPUT policy to DROP. Work on a physical machine or via console when first configuring firewall rules.

🔄 NAT, Masquerading & Connection Tracking

NAT allows a Linux machine to act as a router/gateway, sharing internet access or forwarding ports. The kernel's conntrack subsystem tracks stateful bi-directional streams.

bash — NAT & port forwarding
# Enable IP forwarding first $ sudo sysctl -w net.ipv4.ip_forward=1
# MASQUERADE: share internet (ens3 = WAN interface) $ sudo iptables -t nat -A POSTROUTING \ -o ens3 -j MASQUERADE $ sudo iptables -A FORWARD -i eth1 -o ens3 -j ACCEPT $ sudo iptables -A FORWARD -m conntrack \ --ctstate RELATED,ESTABLISHED -j ACCEPT
# DNAT: port forward 80 → internal server 10.0.0.10:8080 $ sudo iptables -t nat -A PREROUTING \ -p tcp --dport 80 \ -j DNAT --to-destination 10.0.0.10:8080

⚡ nftables

nftables is the modern successor to iptables, with a unified syntax for all address families and better performance.

bash — nftables basics
# List all tables and rules $ sudo nft list ruleset
# Create a simple firewall ruleset $ sudo nft add table inet filter $ sudo nft add chain inet filter input \ '{ type filter hook input priority 0; policy drop; }' $ sudo nft add rule inet filter input \ ct state established,related accept $ sudo nft add rule inet filter input \ iif lo accept $ sudo nft add rule inet filter input \ tcp dport 22 accept $ sudo nft add rule inet filter input \ tcp dport {80, 443} accept
# Save ruleset to file $ sudo nft list ruleset > /etc/nftables.conf

💾 Save & Restore Rules

bash — persistence
# Save current iptables rules $ sudo iptables-save > /etc/iptables/rules.v4 $ sudo ip6tables-save > /etc/iptables/rules.v6
# Restore rules $ sudo iptables-restore < /etc/iptables/rules.v4
# Install iptables-persistent (Debian/Ubuntu) $ sudo apt install iptables-persistent $ sudo netfilter-persistent save $ sudo netfilter-persistent reload
# On RHEL/CentOS with iptables-services $ sudo service iptables save $ sudo systemctl enable iptables

🧪 Lab Exercise

🧪
Lab 02 — Build a Complete iptables Firewall Policy
Estimated time: 20 minutes · Root access required
1
Backup current rules
Run sudo iptables-save > ~/iptables-backup.txt to save your current rules. You can restore them with iptables-restore if needed.
2
Flush existing rules and set policies
Run sudo iptables -F to flush, then set INPUT and FORWARD to DROP, OUTPUT to ACCEPT.
3
Allow essential traffic
Add rules to allow: loopback, established connections, SSH (22), HTTP (80), HTTPS (443), and ICMP.
4
Add logging for dropped packets
Insert a LOG rule before the DROP policy: iptables -A INPUT -j LOG --log-prefix "DROPPED: " --log-level 4
5
Test the rules
From another machine, try to connect to SSH (should work), then to a blocked port like 8080 (should be blocked). Check /var/log/syslog for dropped packet logs.
6
Save and restore rules
Save rules with iptables-save, then test by flushing and restoring from file.
