Network Security Hardening

Hardening is the process of reducing the attack surface of a Linux system. This final module covers SSH configuration hardening, kernel network parameters, intrusion prevention with fail2ban, and mandatory access control with SELinux.

🕐 ~65 min 🎯 Advanced 📝 5 Quiz Questions

📌 Overview

Network hardening reduces your attack surface — the number of ways an attacker can get in. Core principles:

  • Least Privilege — expose only the services you need
  • Defense in Depth — multiple layers of security
  • Fail Securely — default to deny, not allow
  • Monitor & Alert — log everything, detect anomalies
💡
Security is a process, not a state
Hardening is never complete. Regularly audit your configuration, update packages, and review logs. Use tools like lynis to periodically audit your system.

🔑 SSH Hardening

SSH is the most common remote access vector — and the most commonly attacked. Hardening /etc/ssh/sshd_config is essential.

/etc/ssh/sshd_config — recommended settings
# Change default port (obscurity, not security — but reduces noise) Port 2222
# Disable root login PermitRootLogin no
# Use only SSH key authentication (disable passwords) PasswordAuthentication no ChallengeResponseAuthentication no PubkeyAuthentication yes
# Use only strong ciphers and MACs Ciphers chacha20-poly1305@openssh.com,aes256-gcm@openssh.com MACs hmac-sha2-512-etm@openssh.com,hmac-sha2-256-etm@openssh.com KexAlgorithms curve25519-sha256,diffie-hellman-group16-sha512
# Limit login attempts and timeout MaxAuthTries 3 LoginGraceTime 30 ClientAliveInterval 300 ClientAliveCountMax 2
# Allow only specific users AllowUsers alice bob admin
# Disable X11 forwarding and agent forwarding (unless needed) X11Forwarding no AllowAgentForwarding no AllowTcpForwarding no
# Apply changes $ sudo sshd -t # Test config syntax $ sudo systemctl reload sshd
🚨
Before disabling password auth!
Make absolutely sure your SSH public key is in ~/.ssh/authorized_keys and you can log in with it before disabling password authentication. Test in a new terminal window first!

    ⚙️ Kernel Network Parameters (sysctl)

    The Linux kernel exposes network parameters via /proc/sys/net/ and the sysctl interface. These control key security behaviors.

    /etc/sysctl.d/99-hardening.conf
    # Disable IP forwarding (unless this machine is a router) net.ipv4.ip_forward = 0 net.ipv6.conf.all.forwarding = 0
    # Disable ICMP redirects (prevent routing table manipulation) net.ipv4.conf.all.accept_redirects = 0 net.ipv4.conf.all.send_redirects = 0 net.ipv6.conf.all.accept_redirects = 0
    # Enable TCP SYN cookies (protect against SYN flood attacks) net.ipv4.tcp_syncookies = 1
    # Ignore ICMP broadcast echo requests (Smurf attack protection) net.ipv4.icmp_echo_ignore_broadcasts = 1
    # Ignore bogus ICMP error responses net.ipv4.icmp_ignore_bogus_error_responses = 1
    # Enable reverse path filtering (anti-spoofing) net.ipv4.conf.all.rp_filter = 1 net.ipv4.conf.default.rp_filter = 1
    # Disable source routing net.ipv4.conf.all.accept_source_route = 0
    # Randomize memory layout (ASLR) kernel.randomize_va_space = 2
    # Apply immediately $ sudo sysctl --system

    🚫 fail2ban & Intrusion Defense

    fail2ban scans log files and automatically bans IPs that show signs of malicious behavior (too many failed logins, port scans, etc.) using firewall rules.

    bash — fail2ban setup
    # Install fail2ban $ sudo apt install fail2ban # Debian/Ubuntu $ sudo dnf install fail2ban # RHEL/Fedora
    # Enable and start $ sudo systemctl enable --now fail2ban
    # Create local jail config (don't edit jail.conf directly) $ sudo cp /etc/fail2ban/jail.conf /etc/fail2ban/jail.local $ sudo nano /etc/fail2ban/jail.local
    # Key settings in jail.local [DEFAULT] bantime = 1h findtime = 10m maxretry = 5 banaction = iptables-multiport [sshd] enabled = true port = ssh logpath = /var/log/auth.log maxretry = 3 bantime = 24h
    # Check fail2ban status $ sudo fail2ban-client status $ sudo fail2ban-client status sshd Status for the jail: sshd |- Filter: Currently failed: 2, Total failed: 47 `- Actions: Currently banned: 3, Total banned: 12
    # Manually unban an IP $ sudo fail2ban-client set sshd unbanip 203.0.113.5

    🚪 Port Knocking

    Port knocking hides services behind a "secret knock" — a sequence of connection attempts on specific ports that, when done in order, temporarily open a port.

    bash — knockd setup
    # Install knockd $ sudo apt install knockd
    # /etc/knockd.conf [options] UseSyslog [openSSH] sequence = 7000,8000,9000 seq_timeout = 5 command = /sbin/iptables -A INPUT -s %IP% -p tcp --dport 22 -j ACCEPT tcpflags = syn [closeSSH] sequence = 9000,8000,7000 seq_timeout = 5 command = /sbin/iptables -D INPUT -s %IP% -p tcp --dport 22 -j ACCEPT
    # Start knockd $ sudo systemctl start knockd
    # Client side — perform the knock $ knock server.example.com 7000 8000 9000 $ ssh user@server.example.com # Now SSH is accessible!

    🏛️ SELinux Basics

    SELinux (Security-Enhanced Linux) provides mandatory access control (MAC) — policies that restrict what processes can do, even if they have root privileges.

    bash — SELinux essentials
    # Check SELinux status $ getenforce Enforcing
    $ sestatus SELinux status: enabled SELinuxfs mount: /sys/fs/selinux SELinux mount point: /sys/fs/selinux Loaded policy name: targeted Current mode: enforcing
    # Temporarily switch to permissive (logs but doesn't block) $ sudo setenforce 0
    # List SELinux booleans $ getsebool -a | grep http httpd_can_network_connect --> off
    # Allow Apache to connect to the network $ sudo setsebool -P httpd_can_network_connect on
    # Check SELinux denials in audit log $ sudo ausearch -m avc -ts recent $ sudo sealert -a /var/log/audit/audit.log
    # Change file context $ sudo chcon -t httpd_sys_content_t /var/www/html/mysite $ sudo restorecon -Rv /var/www/html/

    🧪 Lab Exercise

    🧪
    Lab 07 — Harden a Linux Server
    Estimated time: 30 minutes · Root access required
    1
    Audit the current state
    Run ss -tlnp, systemctl list-units --type=service --state=running, and note what's exposed.
    2
    Harden SSH configuration
    Edit /etc/ssh/sshd_config: disable root login, set MaxAuthTries 3, LoginGraceTime 30. Test with sshd -t then reload.
    3
    Apply sysctl hardening
    Create /etc/sysctl.d/99-hardening.conf with the recommended parameters. Apply with sudo sysctl --system.
    4
    Install and configure fail2ban
    Install fail2ban, create jail.local, configure the sshd jail with maxretry=3 and bantime=1h.
    5
    Run lynis security audit
    Install lynis and run sudo lynis audit system. Review the hardening index and recommendations.
