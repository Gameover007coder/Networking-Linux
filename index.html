VPN & Tunneling

Virtual Private Networks create encrypted tunnels across untrusted networks. Linux supports multiple VPN technologies. We cover WireGuard (modern, fast), OpenVPN (battle-tested), and SSH tunnels (quick & easy).

⚡ WireGuard

WireGuard is a modern, extremely fast VPN protocol implemented in the Linux kernel. It uses state-of-the-art cryptography and is much simpler to configure than OpenVPN or IPsec.

bash — WireGuard server setup
# Install WireGuard $ sudo apt install wireguard # Debian/Ubuntu $ sudo dnf install wireguard-tools # RHEL/Fedora
# Generate server key pair $ wg genkey | sudo tee /etc/wireguard/server_private.key $ sudo cat /etc/wireguard/server_private.key | \ wg pubkey | sudo tee /etc/wireguard/server_public.key
# Generate client key pair $ wg genkey | tee client_private.key | wg pubkey > client_public.key
# Create server config /etc/wireguard/wg0.conf $ sudo tee /etc/wireguard/wg0.conf << 'EOF' [Interface] Address = 10.0.0.1/24 ListenPort = 51820 PrivateKey = <SERVER_PRIVATE_KEY> PostUp = iptables -A FORWARD -i %i -j ACCEPT; iptables -t nat -A POSTROUTING -o ens3 -j MASQUERADE PostDown = iptables -D FORWARD -i %i -j ACCEPT; iptables -t nat -D POSTROUTING -o ens3 -j MASQUERADE [Peer] PublicKey = <CLIENT_PUBLIC_KEY> AllowedIPs = 10.0.0.2/32 EOF
# Start WireGuard interface $ sudo wg-quick up wg0 $ sudo systemctl enable wg-quick@wg0
# Check WireGuard status $ sudo wg show
bash — WireGuard client config
# Client config file [Interface] Address = 10.0.0.2/24 PrivateKey = <CLIENT_PRIVATE_KEY> DNS = 1.1.1.1 [Peer] PublicKey = <SERVER_PUBLIC_KEY> Endpoint = server.example.com:51820 AllowedIPs = 0.0.0.0/0 # Route all traffic through VPN PersistentKeepalive = 25

🔒 OpenVPN

OpenVPN is a mature, feature-rich VPN solution using TLS/SSL for encryption. It uses a certificate authority (CA) and client certificates.

bash — OpenVPN quick start
# Install OpenVPN and Easy-RSA $ sudo apt install openvpn easy-rsa
# Initialize PKI with Easy-RSA $ make-cadir ~/openvpn-ca $ cd ~/openvpn-ca $ ./easyrsa init-pki $ ./easyrsa build-ca nopass
# Generate server certificate $ ./easyrsa gen-req server nopass $ ./easyrsa sign-req server server
# Generate Diffie-Hellman parameters $ ./easyrsa gen-dh
# Start OpenVPN with config file $ sudo openvpn --config /etc/openvpn/server.conf $ sudo systemctl start openvpn@server $ sudo systemctl enable openvpn@server

🚇 SSH Tunneling Architectures

SSH tunnels are the fastest, zero-install way to forward ports, encrypt insecure legacy protocols, and bypass restrictive firewalls using an existing SSH shell session.

Local Port Forwarding (-L)
Forward local client port to remote internal target via SSH bastion
ssh -L 8080:internal-db:3306 user@bastion-host
Remote Port Forwarding (-R)
Expose a local port on the remote public server (reverse proxy)
ssh -R 9000:localhost:3000 user@cloud-vps
Dynamic SOCKS5 Proxy (-D)
Create a dynamic encrypted SOCKS5 proxy for browser & curl
ssh -D 1080 -f -N user@remote-gateway
Persistent Daemon Tunnel
Run in background without opening an interactive shell session
ssh -fN -o ServerAliveInterval=30 -L 5432:db:5432 user@jump
bash — SSH tunnel examples
# Access a remote DB (MySQL on port 3306) locally on 13306 $ ssh -L 13306:db-server:3306 user@jump-server # Now connect: mysql -h 127.0.0.1 -P 13306
# SOCKS5 proxy — route browser traffic through server $ ssh -D 1080 -f -N user@remote-server # Configure browser to use SOCKS5 proxy at 127.0.0.1:1080
# Jump host (bastion) to reach internal server $ ssh -J user@bastion user@internal-server

🌐 GRE Tunnels

GRE (Generic Routing Encapsulation) creates a point-to-point tunnel between two hosts. Note: GRE provides no encryption — combine with IPsec for security.

bash — GRE tunnel setup
# Load GRE kernel module $ sudo modprobe ip_gre
# Create GRE tunnel interface # Server A: 192.168.1.10 | Server B: 192.168.2.10 $ sudo ip tunnel add gre1 mode gre \ remote 192.168.2.10 \ local 192.168.1.10 \ ttl 255
$ sudo ip link set gre1 up $ sudo ip addr add 10.10.10.1/30 dev gre1
# Add route for remote network through tunnel $ sudo ip route add 10.10.10.0/30 dev gre1
# Verify tunnel $ ip tunnel show $ ping 10.10.10.2 # Ping remote end of tunnel

🧪 Lab Exercise

🧪
Lab 06 — Set Up a WireGuard Peer-to-Peer VPN
Estimated time: 25 minutes · Requires 2 Linux machines/VMs
1
Install WireGuard on both machines
Run sudo apt install wireguard (or equivalent) on both the server and client.
2
Generate key pairs
On each machine, generate a private key with wg genkey and derive the public key with wg pubkey.
3
Create configuration files
Write /etc/wireguard/wg0.conf on both machines. Server listens on 51820; client connects to server's public IP.
4
Bring up the interface
Run sudo wg-quick up wg0 on both machines. Check status with sudo wg show.
5
Test the tunnel
Ping the peer's WireGuard IP (e.g., 10.0.0.1 from the client). You should see successful replies through the encrypted tunnel.
